# 多套命名显示方案（v1.7.12）

入口：设置 → 我的显示方案。新方案库开始为空，不自动填入预览样例，也不改变当前排版。

## 操作与范围

- 每套包含完整桌面、平板、手机模块位置、尺寸、内边距、字号、字重、动画和侧边栏隐藏设置。只保存既有显示字段，不包含财务数据、颜色系统或新字体。
- 名称为 1–30 个 Unicode 字符，NFKC 规范化并移除首尾空白；拒绝控制及不可见格式字符。ASCII 英文字母大小写不区分，最多 10 套。
- 另存复制当前完整草稿，不自动应用或覆盖已有方案。复制生成新 ID；重命名只更新名称。选中只预览，应用需要独立确认。
- 未保存草稿须先另存或取消切换。另存失败不丢弃草稿；保存成功后仍须再次确认应用。
- 删除只删除所确认 ID 的命名方案，不删除页面或财务资料。与当前已保存配置相同的方案不能直接删除，须先切换。
- 原「自定义首页」、侧边栏显示及当前显示设置保存区保留。应用失败不改变草稿或当前排版。操作完成及取消会恢复键盘焦点，Enter、Escape、Tab 使用原生弹窗行为。

## 独立存储与同步

本机 key 前缀为 `wealth-atlas.named-display-layouts.v1`，按 local、guest、cloud owner 分开；不把未登录时的本机方案自动绑定给账号。方案库与同步祖先放在同一个有版本的 envelope，使用 Web Locks、原始内容比较及单次 localStorage 写入，避免多窗口互相覆盖。缺少锁、读取失败、未知格式或写入失败时保留原内容，不自动清空。

云端使用独立 `public.user_ui_layout_libraries`，不改财务表或既有 `user_ui_preferences` 的 v1 格式。仅本人 SELECT、INSERT、UPDATE library；匿名、DELETE、TRUNCATE、改 owner/revision 均无权限。revision、schema 和时间由 INVOKER trigger 维护。客户端更新必须同时匹配本人 ID 与预期 revision，不用覆盖式 upsert。

库同步不会应用任何方案。确认应用才提交原有当前显示配置，并沿用原来的显示同步。两个同步状态分开显示；“方案库已是最新”不代表当前显示配置或财务资料已同步。旧客户端只处理旧表，不能覆盖新库；旧版修改当前排版后，可能显示“当前显示设置（未命名）”，新库仍保留。

离线保留本机库，重新联网后重试。双方都修改则暂停，明确选择采用哪一整份库，**不是合并**；独有方案可能被所选库替换。确认绑定开窗时的远端 revision 和本机原始内容，后台刷新或其他窗口变更后，旧确认必须重新打开，不静默授权新的覆盖。过期离线版本不能自动复活已删除方案。

原财务 JSON、Excel 和 Obsidian ZIP 不包含这一独立方案库；不能靠恢复财务备份来恢复命名方案。不会自动改写 Vault、读取个人数据库或修改任何财务记录。

## 云端部署与隔离证据

在用户分别批准“恢复项目运行”和“仅新增独立方案库及本人权限”后，部署 `named_display_layout_libraries_v1`。SQL 源文件为 `supabase/named-display-layouts.sql`，SHA-256：`24982650BF769616658D43A0AE4A252D452E5D91AAAD8037AB87D808C40795FC`。

部署前检查新对象无碰撞及旧校验函数；部署后确认旧显示校验函数未变、RLS enabled/forced、本人双向 UPDATE policy 和列权限。云端校验函数以 authenticated 角色执行 32 个虚构输入，32/32 符合预期，未读取任何用户行。虚构不同 owner 的 INSERT 被 `42501` 拒绝并整体回滚，没有创建测试账号或提交记录。

云端安全检查未新增方案库告警。既有“泄露密码保护未启用”告警保持不变，属于账号安全配置范围，本次没有擅自修改。
