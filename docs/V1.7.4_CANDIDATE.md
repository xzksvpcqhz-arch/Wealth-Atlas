# Wealth Atlas v1.7.4 candidate

## Source baseline

- Before this release, GitHub `main` and `v1.7.3` pointed to `6dffc00`, whose package version is 1.6.19. The historical tag will not be moved.
- The complete locally preserved v1.7.3 source is commit `55c7ca6` in the DeepSeek publication project. Its main/preload sources match the public v1.7.3 installer; the older public main differs in the custom-protocol CORS flag.
- This repair branch starts at `55c7ca6`. Neither the old working tree nor existing release tags have been replaced.

## Changes

- Currency columns group accounts within that currency's display partition. Cross-currency child accounts stay visible without changing their saved parent IDs, independent balances, historical transactions or net-worth calculations.
- Existing CSS, theme, navigation and account action handlers are unchanged.
- Automatic updates now use the public GitHub stable feed without credentials, reject downgrades, deduplicate checks and wait for normal quit after a successful download. Returning focus retries a failed check after at least one minute, or checks again after thirty minutes on success.
- Publishing requires a newer version, a clean committed source tree, local and remote tags pointing to that exact commit, and the existing cloud-login build configuration.
- Packaging runs with publishing disabled. Release validation checks the executable/embedded versions, main/preload code equality, signature state and absence of embedded update credentials.
- Uploads create a draft only after validation; the installer, blockmap and update manifest must all be verified before making it public. No existing release is deleted or overwritten.

## Validation performed

- `npm test`: 32 tests plus TypeScript checking.
- `npm run build`: production Next.js build.
- Account UI test: packaged static assets, three synthetic accounts, cross-currency visibility, edit/cancel, archive/cancel, restore, independent balances, unrelated collections unchanged, app restart, Enter/Space and 1440/1280/1024/390/320px layouts.
- Installer-payload tests: blank startup, IndexedDB error paths and migration, diagnostics, edit/delete/restore/persistence, synthetic Obsidian Vault bridge, v1.7.3 to v1.7.4 upgrade and rollback compatibility.
- Windows installer checks: UNSIGNED, expected version, SHA-256 and embedded-code checks passed.
- `npm run release:test-updater`: real NSIS updater over loopback HTTP; newer-version download, same/older version rejection, SHA-512 corruption rejection, no credentials, no immediate quit, normal-quit installation scheduled only once. Actual installer execution is hard-blocked.
- Impeccable detector on the modified UI file: no findings. Existing project design documentation was not rewritten.

## Publication gate and limitations

On 2026-10-25 the user explicitly authorized the commit, v1.7.4 tag and GitHub publication after all scoped tests pass. GitHub credential authentication was checked read-only. The existing cloud frontend configuration was loaded from local user environment variables, with values suppressed and secret/service-role key types rejected. Whitespace-only optional callback values were ignored for this build; persisted system settings were not changed.

Publication still requires a clean committed source, matching local and remote version tags, a rebuilt installer and passing release validation. All three update assets must pass server digest verification before the draft becomes public. A local PASS is not evidence of a public release.

After publication, run `node scripts/updater-feed-test.cjs --public` to verify the actual public GitHub provider and full installer download against the build SHA-256 in a synthetic cache. Actual installation remains hard-blocked. This check is intentionally separate from the local mock/loopback tests.

Actual NSIS installation-wizard/registry behavior, live cloud sign-in, cross-device financial sync and formal Authenticode signing are outside this validation. Payload testing is not a substitute for those checks. No real financial profile or Obsidian Vault was inspected or modified.
